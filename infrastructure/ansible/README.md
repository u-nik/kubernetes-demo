# Kubernetes Cluster Provisioning with Ansible

This directory contains Ansible playbooks to provision a Kubernetes cluster on the Hetzner Cloud infrastructure managed by Terraform.

## Architecture

The cluster consists of:
- **1 Master Node** (node-1): Runs the Kubernetes control plane
- **2 Worker Nodes** (node-2, node-3): Run application workloads

## Prerequisites

1. **Terraform Infrastructure**: The 3 nodes must already be created via Terraform
   ```bash
   cd ../terraform
   terraform apply
   ```

2. **Ansible**: Install Ansible on your local machine
   ```bash
   # Ubuntu/Debian
   sudo apt update
   sudo apt install ansible

   # macOS
   brew install ansible

   # pip
   pip install ansible
   ```

3. **SSH Access**: Ensure you can SSH into the nodes as root using the SSH key configured in Terraform

4. **jq**: Required for the inventory generation script
   ```bash
   # Ubuntu/Debian
   sudo apt install jq

   # macOS
   brew install jq
   ```

## Quick Start

### 1. Generate Ansible Inventory

After creating the infrastructure with Terraform, generate the Ansible inventory from the Terraform outputs:

```bash
./generate-inventory.sh
```

This will create an `inventory.ini` file with the IP addresses of all nodes.

### 2. Provision the Kubernetes Cluster

Run the main playbook to provision the complete cluster:

```bash
ansible-playbook site.yml
```

This will:
1. Prepare all nodes (install container runtime, Kubernetes packages, etc.)
2. Initialize the Kubernetes control plane on the master node
3. Join the worker nodes to the cluster

The process takes approximately 10-15 minutes.

### 3. Access the Cluster

After provisioning, you can access the cluster from the master node:

```bash
ssh root@<MASTER_IP>
kubectl get nodes
```

To use kubectl from your local machine, copy the kubeconfig from the master:

```bash
ssh root@<MASTER_IP> cat /etc/kubernetes/admin.conf > ~/.kube/config-hetzner
export KUBECONFIG=~/.kube/config-hetzner
kubectl get nodes
```

## Playbook Details

### Individual Playbooks

You can also run individual playbooks separately:

#### 1. Prepare Nodes (`01-prepare-nodes.yml`)

Prepares all nodes with:
- Container runtime (containerd)
- Kubernetes packages (kubeadm, kubelet, kubectl)
- Required kernel modules and sysctl settings
- Network prerequisites

```bash
ansible-playbook 01-prepare-nodes.yml
```

#### 2. Initialize Master (`02-init-master.yml`)

Initializes the Kubernetes control plane on the master node:
- Runs `kubeadm init`
- Installs Calico CNI for pod networking
- Generates the join token for worker nodes

```bash
ansible-playbook 02-init-master.yml
```

#### 3. Join Workers (`03-join-workers.yml`)

Joins worker nodes to the cluster using the token generated by the master:

```bash
ansible-playbook 03-join-workers.yml
```

## Kubernetes Version

The playbooks install **Kubernetes v1.29** (stable), which is compatible with Ubuntu 24.04.

## Network Plugin

The cluster uses **Calico** as the CNI (Container Network Interface) plugin with the pod network CIDR `10.244.0.0/16`.

## Configuration

### Changing Kubernetes Version

To use a different Kubernetes version, modify the repository URL in `01-prepare-nodes.yml`:

```yaml
- name: Add Kubernetes repository
  apt_repository:
    repo: "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /"
```

### Changing CNI Plugin

To use a different CNI plugin (e.g., Flannel, Weave), modify the installation task in `02-init-master.yml`.

## Troubleshooting

### SSH Connection Issues

If Ansible cannot connect to the nodes:

1. Verify the inventory file has correct IP addresses
2. Test SSH access manually:
   ```bash
   ssh root@<IP_ADDRESS>
   ```
3. Ensure your SSH key is loaded in the SSH agent

### Cluster Initialization Fails

If kubeadm init fails:

1. Check the error message in the Ansible output
2. SSH to the master node and check logs:
   ```bash
   journalctl -xeu kubelet
   ```
3. Reset and try again:
   ```bash
   kubeadm reset -f
   ```

### Worker Nodes Won't Join

If worker nodes fail to join:

1. Check that the master node is fully initialized
2. Regenerate the join token on the master:
   ```bash
   kubeadm token create --print-join-command
   ```
3. Manually run the join command on worker nodes

## Manual Verification

After provisioning, verify the cluster:

```bash
# On master node
kubectl get nodes
kubectl get pods -A
kubectl cluster-info

# Check component status
kubectl get componentstatuses
```

All nodes should show as "Ready" and all system pods should be running.

## Cleanup

To destroy the cluster and infrastructure:

```bash
# Destroy infrastructure
cd ../terraform
terraform destroy
```
